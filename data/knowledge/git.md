# Git

> Distributed version control: commits, branches, merges and pull requests.
> Category: Tools. Typical effort: about 2 study days.

## Version control basics

- **Repository** — folder whose history Git tracks.
- **Commit** — saved snapshot of your files with a message.
- **Staging area** — holding zone for changes chosen for the next commit.

Practice: Init a repo, make five commits and read git log.

## Branching and merging

- **Branch** — independent line of development.
- **Merge** — combines the history of two branches.
- **HEAD** — pointer to the commit you currently have checked out.

Practice: Create a feature branch, commit on it and merge it back.

## Remotes and pull requests

- **git push** — uploads local commits to a remote.
- **Pull request** — proposes changes for review before merging.
- **Fork** — your own copy of someone else's repository.

Practice: Push to GitHub and open a pull request on your own repo.

## Fixing mistakes

- **git revert** — creates a new commit that undoes an earlier one.
- **Merge conflict** — two branches changed the same lines.
- **git stash** — temporarily shelves uncommitted changes.

Practice: Create and resolve a merge conflict on purpose.

## Mini project

Create a repository with a README, at least three feature branches merged through pull requests and a resolved merge conflict.
